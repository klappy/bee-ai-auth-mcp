# Production source deployment

Feature branches merge to main (staging). Production is promoted only by the reviewed main → production PR. This script is invoked by the existing production-only Cloudflare Git Build; it does not change that trigger. Proposed build command: `npm ci && node scripts/gen-version.mjs && npm run typecheck && npm test`. Proposed deploy command: `node scripts/deploy-production.cjs`. Otto must independently review and apply the actual trigger change before promotion.

`deploy/production-prerequisites.json` deliberately ships with `accepted:false`. A later reviewed PR records the actual independently accepted active configuration version/deployment, Access app/policy IDs, audiences, trusted owner-policy match receipt, reviewed main ancestor, and approved positive recurring monthly policy. No default quota, secret, private identity, identity hash or test grant belongs in that file. Preparing this script is not accepting those prerequisites.

The Build fails before any provider request if that manifest or Git source stamp is incomplete. It verifies production storage and required inherited secret names, configured policy, private Container image/allocation/logging, Worker logging, ordinary workers.dev enabled and preview URLs disabled. Infrastructure writes are deliberately absent: no Container rollout, Access creation, secret APIs, settings mutation, storage migration or billing activation occurs here.

It preserves all existing writable version metadata and bindings, inheriting secrets. The single approved homepage module is compiled into a generated asset map, preserving other public paths and MIME types. The exact obsolete review-only banner is removed only after accepted enabled monthly policy passes preflight; every other approved homepage byte stays unchanged, including the paid-signup notice. Staging's canonical preview retains its banner. Explicit Worker-first routing supersedes old external homepage bytes; the hosted entry's reserved protocol/identity routes remain outside asset handling.

Version upload uses `deploy=false`. Exact candidate module bytes, normalized bindings and metadata are read and compared before explicit 100% deployment. Live settings/deployment are re-read between upload and deploy; unexpected drift aborts. Active source/version, settings, private runtime, image, domain, staging and public protocol responses are read back. An upload is not deployment; a deployed source with failed readback is a failed build with `source_deployed:true`, never an automatic rollback. Only a separate observed-failure rollback may proceed under the release envelope.

The receipt contains safe identifiers, hashes of public source and booleans only. API bodies, arbitrary exceptions, secret values and private identities are never printed. Public checks do not perform authenticated Bee retrieval, enroll users or prove cross-user/cleanup acceptance. Empty instances prove only no currently listed instance; runtime acceptance is a separate release check.

The generated Build SHA must equal WORKERS_CI_COMMIT_SHA; Git must prove the manifest reviewedMain is its ancestor. Missing shallow history refuses deployment. Ancestry is separate from the final promotion commit stamp and does not require a self-referential manifest hash. Narrow Access destinations, OTP provider, policy shape and snapshots are checked without persisting private policy content. The accepted provider receipt supplies the prior trusted owner-policy match; secret read APIs cannot recover an owner identity to re-prove that equality.
