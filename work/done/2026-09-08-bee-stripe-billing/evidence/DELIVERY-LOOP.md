3. **Establish a real receiver.** Auggie records acceptance and verified execution/return capability before claiming delegation is active. Retain existing workers where their claims are current. 4. **Plan before new builds.** Recover accepted plans for existing dishes rather than recooking them. Do not repeatedly poll an impossible preview or dispatch duplicate nudges instead of identifying an actionable gap.
6. **Validate, repair, release.** Independent review checks the declared behavior and drift caused by the change. Resolve blocking findings through a bounded revision and fresh applicable checks. Current CI/Bugbot, deployable image/provider behavior and hosted end-to-end evidence remain distinct. The designated expeditor verifies release authorization and the actual production trigger; after landing, observe live version and consumer acceptance. Never substitute upload, merge, PR metadata or payment-link creation for the customer's completed journey.
7. **Learn and repeat.** Move accepted dishes through the current debrief/learning lanes. Answer the three-loop review: what failed, what produced it, and whether the learning machinery caught it cheaply. Land product lessons in the product's authoritative knowledge home; promote shared practice changes by governed review. Update the checkpoint and journal, then choose the next eligible unmet goal in this active execution context.

## Clean resting states, not false endings

- **Complete:** all scoped goals have evidence, required dishes are accepted/landed, and learning obligations have a recorded disposition. Only then close the meal.
- **Partial release:** invited-family onboarding is accepted but billing remains queued. Label milestone A complete and the meal incomplete; do not imply billing is done.
- **Waiting on a real dependency/check:** record the exact dependency, owner, last evidence and resume trigger; continue independent authorized work. A queued/in-progress check is neither passed nor absent.
- **Human-only decision:** return one exact question with recommendation and review material; preserve the ready work. Do not ask for credentials in chat or turn Klappy into a task courier.
- **Capability or exhausted-budget boundary:** preserve cargo, actual failure and next authorized action. Do not reset the promise, escalate to a more expensive execution lane by default or claim background continuation.

Recorded / dispatched / acknowledged / running / validated / released / learned are separate evidence claims. This loop runs only through an actual active coordinator or a separately authorized, proven automation. No schedule, monitor or runtime has been created by this file.
